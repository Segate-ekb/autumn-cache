# autumn-cache

Кэширование результатов методов желудей [ОСени](https://github.com/autumn-library/autumn)
по аннотациям — аналог `@Cacheable` / `@CacheEvict` из Spring. Поставщики в памяти и в
файлах, общий бюджет памяти в байтах, настройки для каждого кэша по имени, вытеснение
сегментированным LRU, срок жизни записей, счётчики попаданий, промахов и вытеснений.

## Установка

```bash
opm install autumn-cache
```

Нужен `decorator` с типом перехватчика `ТипыПерехватчиковМетода.Вместо` (3.1.0 и новее).

## Быстрый старт

```bsl
#Использовать autumn
#Использовать autumn-cache

&Кэшируемый("настройки")
Функция Настройка(&КлючКэша Раздел, &КлючКэша Имя, ПоУмолчанию) Экспорт
	// Вызывается только на промахе: повторный вызов с теми же Раздел и Имя берёт значение из кэша.
КонецФункции

&СбрасываетКэш("настройки")
Процедура СохранитьНастройку(&КлючКэша Раздел, &КлючКэша Имя, Значение) Экспорт
	// После успешного вызова запись с этим ключом удаляется.
КонецПроцедуры

&СбрасываетКэш(Значение = "настройки", ВсеЗаписи = Истина)
Процедура ПерезагрузитьНастройки() Экспорт
КонецПроцедуры
```

## Аннотации

| Аннотация | Где | Что делает |
|---|---|---|
| `&Кэшируемый("<имя>")` | экспортная функция желудя | результат хранится в кэше `<имя>` |
| `&КлючКэша` | параметр метода | значение параметра входит в ключ |
| `&СбрасываетКэш("<имя>")` | экспортный метод желудя, можно несколько | после успешного вызова удаляет запись по ключу |
| `&СбрасываетКэш(Значение = "<имя>", ВсеЗаписи = Истина)` | экспортный метод желудя | после успешного вызова очищает кэш |

Ключ — значения параметров с `&КлючКэша` в порядке объявления, а если таких нет — всех
параметров. В ключ входят только `Строка`, `Число`, `Дата`, `Булево`,
`УникальныйИдентификатор` и `Неопределено`; объект в ключе — исключение при вызове.
`1` и `1.0` — один ключ, `"1"` и `1` — разные.

Не кэшируются исключения, `Неопределено` и `NULL`. Если кэш сбросили, пока метод выполнялся,
его результат не кладётся. `&Кэшируемый` на процедуре и аннотации кэша на неэкспортном методе —
ошибка при сборке желудя.

Напильник кэша стоит на `&Порядок(400)`, внутри напильников телеметрии (500 и выше): попадания
видны телеметрии как вызовы метода. Кэш заменяет вызов перехватчиком `Вместо`, поэтому напильники
с меньшим порядком выполняются только на промахе, вместе с самим методом.

## Настройки

Каждый кэш настраивается по своему имени, ключами `cache.<имя>.*`:

| Ключ | Значение | По умолчанию |
|---|---|---|
| `Поставщик` | `память` или `файлы` | `память` |
| `Предел` | записей для памяти, байт для файлов | для памяти — общий бюджет или 1000 записей; для файлов обязателен |
| `СрокЖизни` | секунды от записи, дробные допустимы | бессрочно |
| `Каталог` | каталог файлового кэша | для файлов обязателен |

```json
{
  "cache": {
    "отчёты": { "Поставщик": "файлы", "Каталог": "./cache/reports", "Предел": 2147483648 },
    "настройки": { "Поставщик": "память", "Предел": 1000, "СрокЖизни": 30 }
  }
}
```

Кэш без настроек и без `cache.ПределПамяти` живёт в памяти с пределом 1000 записей: безразмерного
кэша нет. Фактические настройки каждого кэша пишутся в журнал `oscript.lib.autumn-cache` при его
создании: опечатка в ключе видна там.

### Общий бюджет памяти

`cache.ПределПамяти` — байты на все кэши в памяти, у которых не задан свой `Предел`. Такие кэши
делят один сегментированный LRU: память достаётся записям, к которым обращаются чаще, в каком бы
кэше они ни были. Вес записи — оценка памяти под запись целиком: 1750 байт на саму запись, её
место в индексе и в очереди, плюс ключ и значение по формулам, снятым замером OneScript 2.2.
На 100–200 тыс. записей с ключом из двух частей и значением `Булево`, `Число` или
`ФиксированнаяСтруктура` из трёх полей оценка ниже реального прироста памяти процесса на 1–5 %;
для отдельных видов значений расхождение доходит до ±15 %. К памяти процесса добавляются его
собственные ~80 МБ и запас сборщика мусора — бюджет ставьте с запасом. Запись тяжелее десятой
доли бюджета не кладётся, поэтому бюджет меньше ~18 КБ не примет ни одной записи: одни накладные
весят 1750 байт. Имя кэша «ПределПамяти» занято.

Кэш с общим бюджетом отдаёт вызывающему ту же ссылку, что хранит, поэтому принимает только
неизменяемые значения: `Строка`, `Число`, `Дата`, `Булево`, `УникальныйИдентификатор`,
`ДвоичныеДанные` и `ФиксированнаяСтруктура`, `ФиксированноеСоответствие`, `ФиксированныйМассив`
из них. `Структура`, `Соответствие`, `Массив`, `ТаблицаЗначений`, объекты и сущности не
кладутся: метод с `&Кэшируемый` работает без кэша и пишет ошибку в журнал, программный
`Кэш.Положить` вызывает исключение. Результат из базы возвращайте фиксированной коллекцией.

Без `cache.ПределПамяти` кэши в памяти работают как в 0.1: предел в записях, любые значения.

Сброс виден только в своём процессе. Если приложение запущено в нескольких процессах, задавайте
кэшам чтения из базы `СрокЖизни`: иначе другие процессы отдают старое значение до вытеснения.

### Журнал

На уровне отладки журнал `oscript.lib.autumn-cache` показывает каждый шаг с числами: промах и
попадание, положено (занято бюджета из предела) или нет и почему, вытеснение (давление на предел),
истечение, сброс. Строки вида `Кэш "имя": событие, ключ К, числа`. Ключи кэша попадают в этот
журнал, в том числе в строку ошибки, когда результат метода не удалось положить, — не делайте
ключом секреты.

Файловый кэш хранит только `ДвоичныеДанные`. Значение другого типа не кэшируется, а ошибка
пишется в журнал; программный `Кэш.Положить` в этом случае вызывает исключение. Файл
тяжелее десятой доли предела не кэшируется. При создании кэша из каталога удаляются файлы
`*.cache` прошлого запуска — каталог принадлежит одному кэшу одного процесса.

## Программный доступ

```bsl
Перем КэшНастроек;

Процедура ЗабытьНастройку(Раздел, Имя) Экспорт
	КэшНастроек.Удалить(Новый КлючКэша().Добавить(Раздел).Добавить(Имя));
КонецПроцедуры

Функция ПопаданийВКэшНастроек() Экспорт
	Возврат КэшНастроек.Статистика().Попадания;
КонецФункции

&Желудь
Процедура ПриСозданииОбъекта(&Пластилин МенеджерКэшей)
	КэшНастроек = МенеджерКэшей.Кэш("настройки");
КонецПроцедуры
```

| Класс | Метод | Что делает |
|---|---|---|
| `МенеджерКэшей` (желудь) | `Кэш(Имя)` | кэш по имени, тот же, что у аннотаций |
| `Кэш` | `Получить(Ключ)` | значение или `Неопределено` |
| | `Положить(Ключ, Значение)` | кладёт с вытеснением сверх предела |
| | `Удалить(Ключ)`, `Очистить()` | удаляет запись или все записи; то, что пишется в этот момент, не кладётся |
| | `Статистика()` | `Структура("Попадания, Промахи, Вытеснения, Занято")`; `Занято` — записи или байты |
| `КлючКэша` | `Добавить(Значение)` | ключ из нескольких частей; одиночное значение равно ключу из одной части |

## Вытеснение

Сегментированный LRU: новая запись попадает в испытательный сегмент, повторное обращение
переводит её в защищённый (до 80 % предела), переполнение защищённого возвращает его хвост
на испытание. Вытесняется хвост испытательного сегмента, поэтому проход по множеству
разовых ключей не вымывает часто запрашиваемые записи. Вес записи — 1 в памяти с пределом
в записях, оценка записи целиком в общем бюджете памяти и размер файла в байтах в файлах;
вес файла, который сейчас пишется, уже занят, поэтому файлы кэша держатся
в пределе. Исключение — Windows: файл, открытый читателем в момент вытеснения, не удаляется и
остаётся вне учёта до перезапуска.

## Ограничения

- Параллельные промахи по одному ключу вызывают исходный метод каждый.
- Вызов через `ЭтотОбъект` внутри желудя идёт мимо кэша.
- Кэш — общее пространство ключей для всех методов с этим именем кэша: ключ не содержит
  имени метода, поэтому `&СбрасываетКэш` работает из другого метода.
- Кэш в памяти с пределом в записях хранит ссылки: изменение возвращённого объекта меняет и кэш.
- Попадание в файловый кэш читает файл целиком.
- Срок жизни проверяется при обращении: истёкшая запись занимает место до обращения или
  вытеснения по пределу.
- Поколение одно на кэш: любой сброс отбрасывает все записи, которые пишутся в этот момент,
  поэтому частые сбросы снижают долю попаданий.
